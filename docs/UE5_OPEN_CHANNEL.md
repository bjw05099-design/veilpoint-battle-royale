# VEILPOINT CH02 · Open Channel

Open Channel은 CH01 마지막 인계 후 조현지에게 돌아가 확인 대화를
끝내면 같은 Unreal 아덴 월드에서 이어지는 후속 장면이다. 이야기는
창작이며 일반 공개 도로 중심선에 경로를 배치했다. 시설명이나 실내
배치 없이 공개 지형, 도로, 외곽의 원본 좌표를 유지한다.

1. 구호 데스크의 브리핑 기록을 확인한다.
2. 교차로에서 증언 인터뷰 또는 공개 공고 확인을 선택한다.
3. 선택한 지점에서 물자 도착 사실과 아직 확인할 수 없는 정보를 구분한다.
4. 양쪽 길이 합류하는 지점에서 장부와 기록을 대조한다.
5. 확인된 내용을 공지한다. 모든 이름을 확인 처리하면 살마가 반려한다.

F로 조사하고 1·2로 응답한다. M의 현장 지도에는 선택한 현재 구간이
공개 도로를 따라 표시된다. HUD는 지점 직선거리와 현재 경로의 남은
거리를 따로 보여준다. J 기록에는 실제로 확인한 정보만 나온다.
F6는 진행 상황을 저장하고, F7은 믿을 수 있는 마지막 저장 지점으로
복귀한다. 버전 1·2 저장은 진행과 기록을 유지하며, 이후 저장부터
버전 3 형식으로 분기를 담는다.

아덴 맵의 현재 조사 지점에는 플레이용 3D 표지가 나타난다. 바람,
세 가지 발소리, 기록 확인음을 프로젝트 스크립트로 합성해 Unreal
에디터에서 SoundWave로 가져온다. K는 현장 음향을 켜고 끄며 로컬
사용자 설정에 기록한다. 기술 음향에는 실제 현장 녹음이 포함되지 않는다.

자동 패키지 검사는 양쪽 경로에서 캡슐을 지형 위로 스윕하고, 실제
상호작용으로 선택과 거부 조건을 검사한다. 중간 저장 복귀 후 분기가
유지되는지 확인하고, 지도 경로와 후속 챕터 종료 화면을 저장한다.

## CH04 · Signed Receipt

CH03에서 정정 사항을 전달하면 기존 공개 공지 또는 구호 데스크 결말에
따라 아미나나 유수프가 수령 기록을 요청한다. 장부 지점에서 마라의 서명을
받고 등록된 공공 도로를 따라 약 145m 떨어진 기록 지점에서 나빌에게
인계한다. 서명은 사본의 수령을 확인하며, 가족의 요청은 계속 열린 상태로
남는다. 등장인물과 정거장은 창작이다.

현장 지도는 도로 기준의 현재 위치에서 앞으로 남은 길을 강조한다.
F6/F7과 자동 체크포인트는 버전 6에서 영수증 진행을 보존한다.
이전 CH03 완료 저장은 해당 결말의 출발 지점에서 이어진다.
F7은 기본 저장을 우선 확인하고 손상된 경우 검증된 백업으로 복귀한다.
두 슬롯 모두 유효하지 않으면 현재 진행과 위치를 유지한다. 패키지
검사는 두 CH04 결말에서 별도 테스트 슬롯을 손상시켜 각각 확인한다.
패키지 검사는 두 결말로부터 이어지는 보행, 상호작용 범위, 복귀와 인계를 확인한다.

## CH05 · Pending Reply

CH04 수령 기록을 보관한 뒤 나빌에게 새로 들어온 회신을 묻는다.
교차로에서 회신 기록을 받고, 이전에 공개 공고를 정정했다면 아미나의
서명이 담긴 공개본을 확인한다. 구호 데스크로 전달했다면 유수프의
전화 낭독 기록을 확인한다. 해당 증거를 1 또는 2로 선택한 뒤 다음
정거장에 인계한다. 잘못 분류한 증거는 거부되고 선택을 다시 할 수 있다.
어느 결말에서도 기존 가족 요청은 열린 상태로 남는다.

두 보행 경로는 각각 약 351m, 458m다. 등록된 공개 도로와 건물 외곽
자료로 경로를 검사했다. 정거장과 이야기는 창작이다. 버전 6의 CH04
완료 체크포인트는 보관소의 새 대화 위치로 복귀한다. 버전 7은 CH05
진행과 기존 분기를 함께 기록한다. Windows 패키지 검사는 두 경로의
보행, 증거 오답 거부, 분기 유지와 저장 복귀를 확인하도록 구성했다.

## 배틀로얄 개발 검증

Development 빌드의 BR_Development는 분리된 기존 합성 시험 환경이다.
준비 로비에서는 들어온 플레이어들이 Enter로 준비를 확인한 뒤 게임이
시작된다. 게임 시작 후에는 기존 경기의 참가 인원이 고정된다.
로비에는 서버 정보를 기준으로 참가자 대기, 준비 대기, 카운트다운,
경기 시작 확인이 구분되어 표시된다.
종료 화면은 서버가 기록한 결과와 경기 시간을 표시한다.

Windows 자동 검사는 로컬 루프백에서 실제 Unreal 프로세스 두 개로
호스트와 클라이언트를 실행한다. 두 플레이어가 준비할 때까지 경기
시작이 보류되는지, 종료 후 각 이동 기록이 소유자에게만 전달되는지
확인한다. 배틀로얄 공개 출시와 96인 인터넷 대전에는 별도 검증이 필요하다.
경기 시작 시 서버에서 참가 명단을 고정하고 연결을 종료한 참가자를
생존 집계에서 제거한다. 별도의 루프백 경기에서 진행 중 클라이언트가
종료했을 때 남은 호스트의 1위와 이동 기록 확정을 검사한다.
경기 전 카운트다운 도중 클라이언트가 이탈하는 경우도 검사한다. 서버는
카운트다운을 취소하고, 재입장한 플레이어가 준비를 누르고 두 명이 준비된
뒤에 새 카운트다운을 시작해야 한다.
