# VEILPOINT Windows 검증 대기 목록

## 빌드 대상

- 직전 Windows 성공본은 `95b9d8d7840d8045a5c5898ceec015a866c852f7`이다. 이 패키지는 아덴 보행과 기능 회귀를 확인할 때 사용한다.
- 이번 빌드 대상은 `764b471ab6a60f2a978fd1c99eeac2249d81a063`이다. 기존 아덴 충돌 구역, 12장 연결과 저장 복구, 5분 오프닝, 총기 시제품, 젖은 지면과 배틀로얄 준비 상태를 포함한다. 이전 대기 항목인 개인 핀, 조준 전환, 분기 경로 길이와 배틀로얄 배속 재생을 함께 검사한다. 이번 회차의 아덴 경사 보행과 경로 복귀, CH02 분기별 장비, 배틀로얄 준비 단계 장비 선택도 추가했다.
- **상태는 시작 지시 대기.** PC에서 실행기 창이 닫혀 있다면 `START_BUILD_PC.cmd`로 연다. 처음 보이는 `Listening for Jobs`와 전용 저장소 Actions의 활성 작업을 확인한다. 이미 진행 중인 작업은 종료 결과부터 확인한다.

시작 지시가 오면 아래 요청으로 전용 Windows 실행기에 `author-package` 한 건을 넣는다. 이 작업에서 사전 점검, C++ 컴파일, 레벨 저작, 패키징과 실행 검사를 차례대로 수행한다. 실행 전 게임 저장소 `main`이 앞섰다면 이 기준점 이후의 변경을 먼저 확인해 빌드 대상을 확정한다.

```json
{
  "schema": "veilpoint-pc-build-v1",
  "source_sha": "764b471ab6a60f2a978fd1c99eeac2249d81a063",
  "operation": "author-package"
}
```

실패하면 첫 실패 단계와 로그를 확인한다. 같은 원인으로 반복 실행하기 전에 소스나 실행기에서 원인을 해결한다. 기존 패키지와 저장은 복구와 기능 회귀 확인에 쓸 수 있도록 보관한다. [실행기와 로그 경로](GAME_DEV_TOOLCHAIN.md#네이티브-패키지-조작과-화면-검사)

## 패키지가 나온 뒤 직접 확인할 것

1. 검증된 새 패키지의 `PLAY_VEILPOINT.cmd`로 실행한다. 기존 저장을 옮기기 전에 첫 화면부터 한 번 재생한다. **이수혁 독백의 발음과 자막 싱크, 음량, ESC 일시 정지·재개, 배에서 내린 뒤 마우스와 WASD가 바로 동작하는 순간**을 확인한다. 자동 오프스크린 검사는 음소거 상태이므로 청취 검사는 직접 한다.
2. CH01에서 F 상호작용과 F7 복귀를 시험한다. M 현장 지도에서 최대 확대, 방향키 이동과 Home 복귀, P 배치와 Delete 삭제를 확인한다. 1인칭에서 가까운 핀이 벽에 가려지면 표시가 사라지는지 본다. 표시된 길을 따라가다가 24m 이상 벗어나 M 지도에서 복귀 방향 점선과 거리를 확인한다. 같은 아덴 경사면을 오르내리며 속도 전환, 방향 반전, 평지 복귀, 앉아서 이동하는 감각을 확인한다. 지도 입력과 지면 발소리, J 교신 기록도 확인한다.
3. CH02와 CH07의 선택지에서 M과 1·2로 두 길의 표시와 길이를 확인한 뒤 1인칭에서 선택을 확정한다. CH02 교전에서 1인칭 총기, 우클릭 조준, 벽 앞 총기 내림과 벽에서 물러났을 때의 복귀를 확인한다. 빈 탄창과 탄이 남은 탄창의 재장전 동작, 탄약 표시, 과열과 냉각도 비교한다. 유수프 분기의 Compact가 짧은 1인칭 모델로 보이고 F7 복귀 후에도 선택 분기와 장비가 맞는지 확인한다.
4. 배틀로얄 로컬 호스트·클라이언트에서 V로 Patrol과 Compact를 전환해 탄약 표시를 보고, Enter로 준비한 뒤 V가 잠기는지 확인한다. 두 참가자의 시작 전 보급품 보존, 준비 확인 표시와 엄폐 판정도 확인한다. 경기 후 M으로 본인 이동 기록을 열어 T로 1·3·6배속을 바꿀 때 재생 위치가 건너뛰지 않는지 확인한다.

키보드·마우스와 청취 확인은 자동 패키지 검사와 별도로 기록한다. BR의 로컬 검증 결과는 실제 인터넷 참가자와의 대전 결과와 구분한다.
