# VEILPOINT 모델별 개발 작업

이 문서는 개발 세션에서 사용자가 선택한 **Astra 6.2** 또는 **Sol 6.2**에 맞춰 이번에 개발할 일을 고르는 기준이다. 두 모델의 구분은 프로젝트의 작업 배분 기준이다. 기존 [개발 규칙](../AGENTS.md)에 따라 UE5.8 기반 Windows PC 개발, 스토리 우선 분리 출시, **스토리 75%·배틀로얄 25%**를 적용한다. 각 모드에 귀속되는 맵 작업과 안정화도 이 비율에 포함한다. 맵 집중은 사용자가 지정한 회차에 적용한다.

## 작업 배분

| 영역 | Astra 6.2 | Sol 6.2 |
| --- | --- | --- |
| **아덴 맵** | 지형 좌표·정밀도·충돌·렌더링을 함께 바꾸는 작업. 새 지역 연결과 경계 정합성, 지형 스트리밍·LOD 설계, 대표 구간의 UE5.8 구현 및 패키지 검증 | 기준이 정해진 구역의 검증된 원본 데이터 적용, 경계·충돌·지도 UI 수정, 반복 구역 제작, 동일 카메라 캡처와 성능 측정 결과 정리 |
| **스토리** | 여러 장에 영향을 주는 분기와 인물별 결과, 선택과 저장 상태의 연결, 기존 저장이 있는 상태에서 새 구조로 이어지는 방식의 설계·구현 | 승인된 장면·대사·상호작용의 UE5.8 구현, 개별 경로와 HUD 수정, 기존 저장 복귀·두 결말의 회귀 검증 |
| **배틀로얄** | 여러 플레이어가 동시에 영향을 받는 경기 상태와 서버 권한, 이탈·재접속을 포함한 상태 전이, 대규모 검증 설계와 첫 구현 | 이미 정해진 상태 전이 아래 로비·경기 UI 수정, 재현 가능한 단일 오류 해결, 로컬 호스트·클라이언트 회귀 검사와 빌드 확인 |
| **빌드·성능·도구** | 원인이 불명확하거나 여러 시스템에 걸친 CPU·GPU·메모리 병목 분석, 성능 예산과 측정 시나리오 설계, 구조 개선 | 컴파일·패키징·실행 검사, 확정된 시나리오의 반복 측정, 좁은 범위의 빌드 오류 수정, 결과 비교 및 기록 |

## 세션에서 일을 고르는 순서

1. 최신 `main`, 관련 문서, 열린 이슈·PR 및 직전 검증 결과를 확인한다. 진행 중인 변경과 겹치거나 이미 완료된 항목은 후보에서 제외한다.
2. 사용자가 지정한 개발 목표나 이번 회차 범위를 우선 적용한다. 작업 선택을 맡겼다면 현재 모델에 맞는 후보 가운데 다음 플레이 가능 빌드 또는 출시 검증을 직접 진전시키는 일을 고른다.
3. 모델이 세션에서 확인되거나 사용자가 이름을 말한 경우 그 모델 기준을 쓴다. 모델 정보가 없고 목표가 명확하면 주어진 목표를 진행하며, 자유롭게 작업을 고르는 경우에는 표의 작업 성격을 기준으로 고른다.
4. Astra에서 새 설계를 시작할 때는 대표 구간 또는 시나리오를 실제로 구현하고 검증한다. 반복 적용할 부분이 남으면 기준 구현, 수정 범위, 통과 조건을 이슈나 PR에 남긴다. Sol에서 작업 중 기존 기준을 바꿔야 할 문제가 드러나면 재현 결과와 영향 범위를 기록해 다음 구조 변경의 출발점으로 삼는다.
5. PR에 선택한 모델 또는 적용한 작업 기준, 변경 범위, 통과한 검증과 남은 검증을 남긴다. 소스 검사, UE5.8 컴파일, Windows 패키지 실행, 실제 PC 성능 측정은 확인한 단계까지 각각 기록한다.
