# VEILPOINT 모델·추론 수준별 개발 작업

이 문서는 개발 세션에서 사용자가 선택한 **Astra 6.2** 또는 **Sol 6.2**와 추론 수준에 맞춰 이번에 개발할 일을 고르는 기준이다. [개발 규칙](../AGENTS.md)에 따라 UE5.8 기반 Windows PC 개발과 스토리 우선 분리 출시를 적용한다. 장기 개발 비율은 **총기·물리엔진·맵 합계 50%, 스토리 모드 40%, 배틀로얄 10%**다. 두 모드에서 재사용하는 총기·물리 시스템과 지형·충돌·현장 지도는 합산 50%에서 한 번만 집계한다. 각 모드에 적용하는 작업과 안정화는 해당 영역에 반영하며, 사용자가 지정한 회차 범위를 우선한다.

## 작업 배분

| 영역 | Astra 6.2 | Sol 6.2 |
| --- | --- | --- |
| **아덴 맵** | 지형 좌표·정밀도·충돌·렌더링을 함께 바꾸는 작업. 새 지역 연결과 경계 정합성, 지형 스트리밍·LOD 설계, 대표 구간의 UE5.8 구현 및 패키지 검증 | 기준이 정해진 구역의 검증된 원본 데이터 적용, 경계·충돌·지도 UI 수정, 반복 구역 제작, 동일 카메라 캡처와 성능 측정 결과 정리 |
| **총기·물리엔진** | 공통 총기 시스템과 무기별 데이터의 구조, 충돌·움직임 규칙, 멀티플레이 물리 상태의 설계와 대표 구간 검증 | 검증된 총기 외형·모션·파츠 적용, 재장전과 UI 검증, 대표 보행·충돌·물체 상호작용 구현 및 회귀 검사 |
| **스토리** | 여러 장에 영향을 주는 분기와 인물별 결과, 선택과 저장 상태의 연결, 기존 저장이 있는 상태에서 새 구조로 이어지는 방식의 설계·구현 | 승인된 장면·대사·상호작용의 UE5.8 구현, 개별 경로와 HUD 수정, 기존 저장 복귀·두 결말의 회귀 검증 |

## 추론 수준별 작업 범위

모델은 우선 맡길 **작업의 성격**을 정하고, 추론 수준은 한 세션에 묶을 **변경 범위와 검증 깊이**를 정한다. 아래는 프로젝트 기준이다. 세션에서 확인되는 수준이나 사용자가 알려 준 수준을 적용한다.

| 추론 수준 | Astra 6.2 | Sol 6.2 |
| --- | --- | --- |
| **Low** | 영향 범위가 작은 설계 판단 한 건을 확인하고 바로 적용한다. 예를 들어 맵 경계 규칙 하나를 재검토한다. | — |
| **Medium** | 단일 모듈의 미확정 요구나 경계 조건을 정리해 구현한다. 예를 들어 기존 저장 형식 안에서 챕터 진입 조건 하나를 추가한다. | — |
| **High** | 연관된 2~3개 구성 요소에 걸친 설계와 대표 경로를 구현한다. 예를 들어 맵 구역과 충돌 경계를 함께 조정한다. | 여러 재현 조건이 있는 오류를 진단하거나, 검증된 규칙 아래 여러 맵 구역·장면을 구현하고 UE5.8 회귀 검사를 한다. |
| **Extra High (xhigh)** | 좌표·LOD·충돌·성능 예산을 함께 다루는 아덴 확장, 여러 챕터의 분기·저장 전환, 서버 권한이 얽힌 경기 상태 변경을 맡긴다. 대표 시나리오를 구현하고 호환성과 실패 경로를 검증한다. | 기준이 확정된 맵 구역이나 챕터를 묶어 구현하거나, 여러 모듈에 걸친 회귀를 원인별로 좁혀 해결한다. 영향받는 경로, Windows 패키지와 실제 실행까지 확인한다. |
| **Max** | 영향이 큰 전환을 여러 단계로 나눠 대표 경로, 기존 데이터 호환, 복구 가능성을 검증한다. 예를 들어 지형 스트리밍 구조 교체의 첫 배포 구간을 구현한다. | 확정된 전환을 여러 구역이나 시나리오에 적용한다. 기존 자료 호환, 대상별 누락, 회귀 및 빌드 증거를 교차 확인한다. |
| **Ultra** | 맵·게임 상태·성능 목표처럼 여러 시스템의 제약이 충돌하는 결정을 실제 측정과 대안 검증으로 좁히고, 가장 큰 위험을 검증할 구현 구간을 완성한다. | 이미 정해진 구조에서 여러 조건이 겹치는 간헐적 오류나 출시를 막는 회귀를 해결한다. 동일 조건의 반복 실행으로 수정 전후를 비교한다. |

추론 수준이 높을수록 무조건 작업량을 늘리기보다 미확정 조건, 변경의 파급 범위, 검증에 필요한 증거를 기준으로 작업을 묶는다. 어떤 수준에서든 변경한 코드의 필수 검사는 끝낸다. 범위가 이번 세션을 넘으면 독립적으로 플레이하거나 검증할 수 있는 단위로 완료하고 남은 범위를 기록한다.

## Plus 사용량을 고려한 기본 운용

- **Sol 6.2 High**를 일상 개발의 기본값이자 Sol 작업의 최저 추론 수준으로 삼는다. 작은 수정도 High에서 범위를 좁혀 처리한다. 연관된 변경이 많거나 검증 범위가 넓으면 Sol Extra High 이상을 고려한다.
- 구조를 새로 잡아야 하거나 여러 모듈의 판단이 연결되면 **Astra 6.2 High**를 우선 고려한다. 좌표·충돌·렌더링, 분기·저장 호환, 서버 권한·경기 상태가 함께 바뀌면 Astra Extra High를 고려한다. 반복 적용이나 구현량의 증가가 주된 이유라면 Sol High 또는 Extra High가 적합하다.
- **Max·Ultra**는 세션에 해당 수준이 표시되고 기존 시도나 측정 증거로 해결이 어려운 구조 변경, 반복되는 복합 장애, 출시를 막는 문제에만 우선 고려한다. 사용자가 선택한 모델과 추론 수준이 확인되면 그 설정에서 이번 작업의 범위를 정한다.
- 기존 테스트·빌드 로그·캡처를 재사용해 변경 지점부터 확인한다. 범위가 좁으면 관련 검사부터 실행하고, 공통 코드나 패키지 동작에 영향을 주면 필요한 회귀·패키지 검증까지 수행한다. 이미 진행 중인 동일 빌드는 결과를 확인한다.
- 큰 작업은 플레이나 검증이 가능한 구간으로 묶어 완료하고, 다음 세션에서 재현과 구현을 반복하지 않도록 측정값·결정 근거·재현 절차를 저장소에 남긴다. 사용량 숫자는 실제 화면에서 확인할 수 있을 때만 기록한다.

## 세션에서 일을 고르는 순서

1. 최신 `main`, 관련 문서, 열린 이슈·PR 및 직전 검증 결과를 확인한다. 진행 중인 변경과 겹치거나 이미 완료된 항목은 후보에서 제외한다.
2. 사용자가 지정한 개발 목표나 이번 회차 범위를 우선 적용한다. 작업 선택을 맡겼다면 총기·물리엔진·맵 합계 50%, 스토리 40%, 배틀로얄 10%에 맞춰 고른다. 합산 50% 안의 세부 배분은 다음 플레이 구간에 필요한 작업으로 정한다. 대표 구간에서 대사·컷신·목표·교전 배치 변경의 영향과 저장 복귀를 확인한다. [제작 순서와 검증 기준](STORY_FIRST_RELEASE_PLAN.md#reusable-foundations-and-chapter-content)
3. 두 설정이 확인되면 두 표를 함께 적용한다. 한 설정만 확인되면 해당 표를 적용하고, 나머지는 Plus 기본 운용과 작업의 난이도·파급 범위·검증 필요성을 기준으로 판단한다. 두 설정이 확인되지 않아도 명확한 요청은 그대로 진행한다.
4. Astra에서 새 설계를 시작할 때는 대표 구간 또는 시나리오를 실제로 구현하고 검증한다. 반복 적용할 부분이 남으면 기준 구현, 수정 범위, 통과 조건을 이슈나 PR에 남긴다. Sol에서 작업 중 기존 기준을 바꿔야 할 문제가 드러나면 재현 결과와 영향 범위를 기록해 다음 구조 변경의 출발점으로 삼는다.
5. PR에 확인된 모델·추론 수준 또는 적용한 작업 기준, 변경 범위, 통과한 검증과 남은 검증을 남긴다. 소스 검사, UE5.8 컴파일, Windows 패키지 실행, 실제 PC 성능 측정은 확인한 단계까지 각각 기록한다.

## 이전 회차 기록 · 2026-11-22 저녁 개발 후보

아래는 당시 Sol 6.2 Extra High의 작업 선정과 배분 기록이다. 현재 세션의 기준은 위의 장기 개발 비율을 따른다.

| 비중 | 선정한 작업 | 완료 기준 |
| --- | --- | --- |
| **맵 40%** | 아덴 현장 지도에 **현재 구간 전체 보기**를 추가한다. 확대 상태에서도 플레이어·현재 경로·목표를 함께 확인하고 기존 플레이어 중심 보기로 돌아올 수 있게 한다. | 장면 양쪽 경로와 지도 경계 부근에서 경로가 잘리지 않고, 보기 전환 후 기존 확대 상태가 복원된다. 경로가 없는 구간은 기존 지도가 정상 표시된다. 좌표·축척과 지도 조작은 Windows 패키지에서 확인한다. |
| **스토리 모드 50%** | CH04 저장 복귀를 보강한다. 두 결말에서 기본 저장이 손상되면 검증된 백업으로 복귀하고, 유효한 저장이 없으면 F7 후에도 현재 진행과 위치를 유지한다. | 격리된 진단 슬롯에서 백업의 분기·목표·재개 위치가 복원된다. 두 슬롯 모두 무효일 때 진행·위치가 보존되며, 기존 정상 저장도 복귀한다. |
| **배틀로얄 10%** | 기존 로컬 2인 로비 검사에 카운트다운 도중 클라이언트 이탈과 재입장을 추가한다. | 이탈 후 카운트다운이 취소된다. 재입장한 플레이어는 미준비로 시작하고 두 명이 준비를 마친 뒤에만 새 카운트다운을 시작한다. |

작업 시작 시 최신 `main`에서 중복 여부와 기존 입력을 확인한다. 구현 후 한 번의 UE5.8 Windows 패키지에서 세 항목을 함께 검증한다.
