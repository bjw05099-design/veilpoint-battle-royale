# CH01 「마지막 방송」 — 구현 기준과 인수 조건

## 1. 서사 기준 정리

이어지는 대본의 설정: 2015-04-05 아침, 아덴 알무알라 항만 인접 구역. 이수혁·김지윤·조현지가 현지 주민들과 합류한다. 마리암 살림 아와드는 살림 아와드의 딸이자 연락·방송 담당이며, 나딤 하산은 승합차 운전, 살마는 구호소 인계를 담당한다. 유수프 살림은 현지 조정을 맡는다. 파와즈 칼리드는 기존 설정의 인물로 보존하되 확인되지 않은 역할·친족 관계를 새로 확정하지 않는다.

구호물품 인계 중 무장 위협 → 작업장·골목 이동 → 남/동쪽 경로 선택 → 나딤 승합차 합류 → 살마에게 주민 인계 → 철수 차량 진입 불가·대체 탑승지 미확정 → 마리암의 마지막 방송. 주민 구조 성공과 한국팀 귀환 성공을 혼동하지 않는다.

이 문서는 회수된 설정에 근거한 **구현 초안**이다. 다른 대화의 14장면 대본 원문 전체를 확보한 상태가 아니므로 장면 번호·대사를 임의로 확정하지 않는다. 해당 날짜의 실제 전황과 지명·아랍어 발음은 1차 자료 대조 및 현지인 직접 감수가 남아 있다. 이번 작업을 역사 검증 또는 현지 감수 완료로 표시하지 않는다. 기존 나흐린 프로토타입과 그 저장 파일은 유지한다.

## 2. 장면을 플레이로 변환

| 단계 | 실제 게임에서 들어와야 할 판정 | 다음 단계 조건 |
|---|---|---|
| 물품 인계 | 조정 담당자와 가까운 거리에서 F 상호작용 | 생존·권한·시야·도달 확인 |
| 위협 발생 | 현장에서 관측한 사건 | 벽 너머나 전역 알림만으로 사건을 확정하지 않음 |
| 작업장 | 실제 도착 볼륨, 이후 조정 담당자와 대화 | 경로 선택 전 작업장 도착 |
| 남쪽 | 주민 및 물품의 실제 통과 | 두 조건 모두 충족 |
| 동쪽 | 공공 통로의 실제 확인 | 미확인 통로를 안전하다고 선언하지 않음 |
| 승차 | 나딤과 동행 인원 합류 | 인원이 남아 있으면 진행 보류 |
| 구호소 | 살마의 실제 인원 인계 | 인원 확인 완료 |
| 철수 연락 | 차량 진입 불가 및 대체 장소 미확정 | 단순 타이머 종료로 철수 실패를 꾸미지 않음 |
| 방송 | 마리암의 방송 완료 이벤트 | 구조 성공·귀환 미해결로 종료 |

## 3. 코드·데이터

`src/ch01/last-broadcast.js`는 엔진과 독립된 진행 계약이다. 명령 순서, 두 경로, 물리 판정 누락, 종료 후 중복 진행을 검사한다. 상태를 변경하지 않고 새 상태를 반환하며, 저장 복원은 이벤트 이력을 재생해 단계와 경로의 일관성을 검증한다. 이 검사는 로컬 저장 무결성 검사이며 네트워크 인증이나 안티치트가 아니다.

`authority`, `inRange`, `lineOfSight` 등의 값은 신뢰하는 엔진 어댑터가 산출해야 한다. 클라이언트 JSON을 그대로 받는 서버 API로 사용하지 않는다. 현재 기존 `story-slice.js`와 C++ StoryGameState에 자동 연결된 상태는 아니다.

## 4. 맵·그래픽·자산·UI

`node scripts/build-ch01-workshop.cjs`로 `dist/ch01-production/workshop.html`, `production.json`을 만든다. 검토 페이지는 네트워크 의존성이 없는 단일 HTML이다. 아이패드 크기의 브라우저에서 서사 조건·분기·저장 JSON과 맵 개념도를 검토하도록 구성한다. PC 게임을 터치 게임으로 바꾸는 화면은 아니다. 실제 iPad Safari 기기 검증은 별도다.

제작 명세는 기존 항구 FBX 10개·UCX 9개를 실제 파일 SHA256로 확인한다. 항구 크기 16×20×9.18m, 출입구 4m, 로컬 중심 (110m,-75m)은 원본 프로토타입 배치이며 실측 아덴 좌표가 아니다. 신규 구호소나 승차 지점을 이 좌표와 동일시하지 않는다. 안뜰 원본의 cm 단위 배치도 포함한다.

방송 소품은 `scripts/blender-build-ch01-radio.py`로 제작한다. 1.2×0.65×1.06m의 탁자·다리·라디오·스피커·마이크·종이 9개 메시, 편집 가능한 .blend, GLB, CPU 렌더 미리보기와 실제 메시 경계 검사를 제공한다. 단색 PBR 원본 블록아웃이며, 실사 텍스처·장비 고증·LOD·UV 품질·게임용 충돌·Unreal 임포트는 미완료다. CI의 실제 Blender 실행 영수증과 구분한다.

조작은 WASD / Shift / C / F / J / L / MMB / ESC를 유지한다. 검토 화면은 44px 이상 버튼, 세로/가로 배치, 키보드 탭 이동, 상태 알림을 사용한다. 예제 체크포인트는 기존 플레이 저장과 섞지 않는다.

## 5. Unreal 인수 계획

1. 최신 14장면 대본 원문과 구현 계약의 차이를 먼저 대조한다.
2. 단계별 엔진 이벤트를 StoryGameState 또는 별도 챕터 컴포넌트에 연결한다. 기존 단순 남/동 출구 완료를 새 CH01 전체 완료로 재해석하지 않는다.
3. 근접·시야·생존은 서버/싱글 권한에서 계산하고 실제 도착·인원·통과를 검사한다. 작업장 도착과 경로 선택은 별도 이벤트다.
4. 라디오 GLB/Blender 원본을 임포트하고 재질·콜리전·눈높이·조명·자막을 검증한다.
5. 양쪽 경로를 새 게임부터 실행해 저장/복원, 문과 주민 통과, 방송 중단/재개를 검사하고 새 EXE를 패키징한다. 실제 창 및 QHD 성능은 PC에서 기록한다.

아이패드 작업으로 가능한 코드·준비 자산·검토 UI와 PC 엔진에서 실제 플레이된 상태를 혼동하지 않는다.
